# P2P Engine 0.6.11 — 2026-10-05

Release metadata and notes are prepared for publication with intended tag
`v0.6.11`. Preparing these notes does not publish, tag, attest or deploy
artifacts; publication remains a separate owner-controlled action. The release
adds durable machine-facing Choice creation, bounded receipt-backed question
contracts and decided Choice supersession by a decided replacement.

Choice creation uses `choice.create` (owner-only locally, external root authority),
bounded explicit input and atomic Choice/receipt/existing worker batch persistence.
Exact operation-key replay preserves the same immutable created ID/outcome.
Decided supersession validates explicit identity and replacement state while
preserving lineage and returning the superseded source to no-decision projection.
The old Choice remains identifiable and links to the new decided Choice, which
is the current decision. No additional event ledger or Choice versioning is
introduced. Mutation status retains the specific transition outcome and replay
fingerprint required to recover an applied decision after response loss.

Question reads expose page/next v1 contracts; keyed mutations use exact question
leaf capabilities, revisions, distinct subject/executor and common recovery.
External root and capability-grant attestations are accepted for exact question
leaves. Convergence updates definition plus questions atomically; proposal apply
only reports `plan_registered` and never writes proposal.md. See
[Question machine contract](../QUESTION-MACHINE-CONTRACT.md).

## Checksums

The existing local candidate build emits SHA256SUMS for its wheel and sdist.
The publication workflow will provide a separate SHA256SUMS for the exact
official artifacts. Verify the selected set before installation:

```bash
sha256sum --check --ignore-missing SHA256SUMS
```

Checksums identify bytes, not signatures. Final source notes and the official
commit timestamp can change the build bytes; do not use the earlier local
candidate's checksum as the future release checksum.

owner-controlled workflow qualifies that exact commit, builds and attests its
artifacts, then creates tag `v0.6.11` and the create-only, attested GitHub Release.

```bash

  --repo BINARYA/p2p-Engine
```

No commit, push, tag, workflow dispatch or publication is performed by this
preparation. Earlier local reproducibility and installed-wheel results remain

handoff; they are not relabeled as published evidence.
