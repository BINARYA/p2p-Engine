# P2P Engine 0.5.1 — 2026-08-28

P2P Engine 0.5.1 was released on 2026-08-28. This release makes uv the
recommended local installation manager while keeping P2P Engine independent
from uv at runtime.

The normal installation is a user-level uv tool environment outside target
projects. A target project does not need its own Python installation or
`.venv`. Existing pip/virtualenv installations remain supported as an explicit
fallback.

## Install

Install the exact release wheel from GitHub with uv-managed Python:

```bash
uv tool install --managed-python --python 3.12 --no-config \
  https://github.com/BINARYA/p2p-Engine/releases/download/v0.5.1/p2p_engine-0.5.1-py3-none-any.whl
```

Run `uv tool update-shell` only if uv reports that its tool binary directory is
not on `PATH`. Installing uv, Python or P2P Engine remains an explicit owner
action; generated agents never mutate the host environment autonomously.

## Compatibility

Version 0.5.1 preserves the 0.5 package boundary (`requires-python >=3.11`),
workspace schema 4, portable vertical schema 3 and the `p2p-cli/v1` JSON
envelope. Python 3.12 is the sole release-qualified runtime; other Python
versions permitted by package metadata are best-effort. The release does not
add workspace migrations or restore removed Git and synchronization product
surfaces.

The recommended portable local runtime uses uv-managed CPython 3.12. The same
candidate wheel is qualified on Linux x86-64, macOS x86-64, Windows x86-64 and
macOS ARM64. Linux and Windows ARM64 are not advertised as qualified.

The Linux x86-64 release gate also exercises installation, upgrade, rollback
and reinstallation across `0.5.0` and `0.5.1` while proving that tool
replacement and removal do not mutate governed project state. The other
platform jobs qualify the new `0.5.1` wheel independently of historical
release behavior.

Version 0.5.1 also replaces the POSIX-only PID liveness probe used by workspace
transaction locks with a non-signalling Windows process query. This prevents
workspace lock status checks from emitting `CTRL_C_EVENT` into the caller's
console group.

## Checksums

The GitHub Release contains `SHA256SUMS` for the exact wheel and source
distribution. Verify the downloaded files before installation:

```bash
sha256sum --check --ignore-missing SHA256SUMS
```

Checksums prove downloaded-byte identity; they are not signatures.

## Provenance

The tag-triggered release workflow creates GitHub Artifact Attestations for the
wheel, source distribution and checksum file. Verify the wheel with:

```bash
gh attestation verify p2p_engine-0.5.1-py3-none-any.whl \
  --repo BINARYA/p2p-Engine
```

The attestation and release assets are produced only after the complete source,
pip-installed and cross-platform uv candidate gates pass for the tagged commit.
