# P2P Engine 0.6.3 — 2026-09-04

P2P Engine 0.6.3 completes durable replication for linked-local WaveKit
projects. Linked mutations now travel as typed, revision-bound commands to the
authoritative server and return immutable, idempotent operation receipts.
Successful commits create one monotone project revision and one ordered
after-state change batch in the P2P-owned filesystem memory.

Linked replicas can recover independently of realtime delivery through a
cursor-based durable feed. Batch application, managed-blob verification, inbox
deduplication and cursor advancement use one local transaction. A client that
falls outside bounded feed retention receives a verified snapshot fallback
instead of silently skipping changes.

The public `p2p sync status|catch-up|recover` commands expose explicit recovery
and diagnostics. `p2p watch` uses authenticated SSE only as an optional wake-up
and always confirms changes through the durable feed. Lost responses reconcile
through operation identity; duplicate commands and batches do not duplicate
effects, and stale same-entity work returns a typed conflict instead of using
last-write-wins.

Linked MCP reads perform freshness preflight, while linked MCP domain writes
route through WaveKit authorization with expected revision and entity evidence.
Raw feed, cursor, storage and compaction primitives remain private worker
surfaces. Offline linked mutations remain blocked, and ephemeral presence is
excluded from canonical memory, bundles and P2P audit.

## Install

Install the exact release wheel from GitHub with uv-managed Python:

```bash
uv tool install --managed-python --python 3.12 --no-config \
  https://github.com/BINARYA/p2p-Engine/releases/download/v0.6.3/p2p_engine-0.6.3-py3-none-any.whl
```

Run `uv tool update-shell` only if uv reports that its tool binary directory is
not on `PATH`. Installing or replacing uv, Python or P2P Engine remains an
explicit owner action.

## Compatibility

Version 0.6.3 keeps `requires-python >=3.11`, workspace schema 4, portable
vertical schema 3, canonical bundle v1 and the `p2p-cli/v1` JSON envelope.
Python 3.12 is the release-qualified runtime. The same candidate wheel is
qualified on Linux x86-64, macOS x86-64, Windows x86-64 and macOS ARM64.

Existing current-schema filesystem projects remain valid and require no
storage or workspace migration from 0.6.2. The filesystem adapter remains the
sole supported product backend; SQLite is not included in this release.
Standalone projects continue to work locally without WaveKit.

Durable linked operation requires a compatible WaveKit server that advertises
`p2p-durable-replication/v1`. Older servers fail capability negotiation rather
than accepting unsupported writes. The protocol remains transport-neutral, so
future WebSocket notification delivery does not change commands, receipts,
change batches or cursors.

## Checksums

The GitHub Release contains `SHA256SUMS` for the exact wheel and source
distribution. Verify downloaded artifacts before installation:

```bash
sha256sum --check --ignore-missing SHA256SUMS
```

Checksums prove downloaded-byte identity; they are not signatures.

## Provenance

The tag-triggered release workflow creates GitHub Artifact Attestations for
the wheel, source distribution and checksum file. Verify the wheel with:

```bash
gh attestation verify p2p_engine-0.6.3-py3-none-any.whl \
  --repo BINARYA/p2p-Engine
```

The release assets are published only from the exact tagged commit after the
source, reproducibility, installed-wheel and cross-platform uv gates pass.
