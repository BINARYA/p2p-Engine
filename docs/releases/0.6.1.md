# P2P Engine 0.6.1 — 2026-09-01

P2P Engine 0.6.1 adds governed project-structure merge and restore workflows
on top of the storage-neutral foundations introduced in 0.6.0. An owner can
compare the current project structure with one exact portable vertical release
or canonical project-memory bundle, resolve stable-ID placements and
collisions, preview the full impact, and apply the result atomically.

Restore uses retained canonical structure snapshots and always creates a new
forward revision. It does not rewind proposal, decision, memory or receipt
history. Merge and restore reuse the existing retirement, readiness and memory
classification rules, and their results are protected by authority-bound
preview tokens, idempotent receipts and recovery operations.

The CLI exposes the complete privileged lifecycle. MCP remains deliberately
read-only for these operations: agents can compare merge sources and inspect
retained snapshots, but cannot apply merge or restore through MCP.

## Install

Install the exact release wheel from GitHub with uv-managed Python:

```bash
uv tool install --managed-python --python 3.12 --no-config \
  https://github.com/BINARYA/p2p-Engine/releases/download/v0.6.1/p2p_engine-0.6.1-py3-none-any.whl
```

Run `uv tool update-shell` only if uv reports that its tool binary directory is
not on `PATH`. Installing or replacing uv, Python or P2P Engine remains an
explicit owner action.

## Compatibility

Version 0.6.1 keeps `requires-python >=3.11`, workspace schema 4, portable
vertical schema 3 and the `p2p-cli/v1` JSON envelope. Python 3.12 is the
release-qualified runtime. The same candidate wheel is qualified on Linux
x86-64, macOS x86-64, Windows x86-64 and macOS ARM64.

Existing current-schema filesystem projects remain valid and require no
storage or workspace migration from 0.6.0. The filesystem adapter remains the
sole supported product backend; SQLite is not included in this release.

Retained structure snapshots are project memory and are included in canonical
memory bundles. They contain logical structure state, not a live database,
journal, WAL, credentials or replica-local configuration. Missing, pruned or
corrupt snapshots fail closed.

## Checksums

The GitHub Release contains `SHA256SUMS` for the exact wheel and source
distribution. Verify downloaded artifacts before installation:

```bash
sha256sum --check --ignore-missing SHA256SUMS
```

Checksums prove downloaded-byte identity; they are not signatures.

## Provenance

The tag-triggered release workflow creates GitHub Artifact Attestations for
the wheel, source distribution and checksum file. Verify the wheel with:

```bash
gh attestation verify p2p_engine-0.6.1-py3-none-any.whl \
  --repo BINARYA/p2p-Engine
```

The release assets are published only from the exact tagged commit after the
source, reproducibility, installed-wheel and cross-platform uv gates pass.
