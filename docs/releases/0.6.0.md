# P2P Engine 0.6.0 — 2026-09-01

P2P Engine 0.6.0 establishes backend-neutral local project-memory foundations
while retaining the filesystem adapter as the sole supported product backend.
It adds stable project identity, canonical logical bundles, typed application
and storage ports, and versioned agent-integration artifacts.

Projects continue to expose the same CLI and MCP abstractions regardless of
the internal filesystem layout. Generated instructions direct agents through
those public interfaces and never require agents to edit YAML, manifests or
storage internals.

## Install

Install the exact release wheel from GitHub with uv-managed Python:

```bash
uv tool install --managed-python --python 3.12 --no-config \
  https://github.com/BINARYA/p2p-Engine/releases/download/v0.6.0/p2p_engine-0.6.0-py3-none-any.whl
```

Run `uv tool update-shell` only if uv reports that its tool binary directory is
not on `PATH`. Installing or replacing uv, Python or P2P Engine remains an
explicit owner action.

## Compatibility

Version 0.6.0 keeps `requires-python >=3.11`, workspace schema 4, portable
vertical schema 3 and the `p2p-cli/v1` JSON envelope. Python 3.12 is the
release-qualified runtime. The same candidate wheel is qualified on Linux
x86-64, macOS x86-64, Windows x86-64 and macOS ARM64.

Existing current-schema filesystem projects remain filesystem projects. A
validated project without the replica-local storage selector requires explicit
filesystem adoption; P2P Engine does not silently choose a different backend
or dual-write. SQLite is not a supported backend in this release.

Stable identity and canonical-memory operations are owner-governed. Logical
`.p2pbundle` archives include portable project data and managed blobs but never
embed replica-local configuration, credentials, a live database, journal or
WAL. Physical `.p2pbackup` archives remain the recovery mechanism for one
local replica.

Project-integration refresh and removal preserve unowned or modified content.
Manifest paths are canonical across POSIX and Windows, including when opening
legacy manifests that contain backslashes.

## Checksums

The GitHub Release contains `SHA256SUMS` for the exact wheel and source
distribution. Verify downloaded artifacts before installation:

```bash
sha256sum --check --ignore-missing SHA256SUMS
```

Checksums prove downloaded-byte identity; they are not signatures.

## Provenance

The tag-triggered release workflow creates GitHub Artifact Attestations for
the wheel, source distribution and checksum file. Verify the wheel with:

```bash
gh attestation verify p2p_engine-0.6.0-py3-none-any.whl \
  --repo BINARYA/p2p-Engine
```

The release assets are published only from the exact tagged commit after the
source, reproducibility, installed-wheel and cross-platform uv gates pass.
